## Project

Fun Run event registration app. Events and their races are read from Postgres; auth is wired up but no registration flow exists yet.

Stack: Next.js 16 (App Router, `src/` dir, TypeScript), React 19, Tailwind CSS v4 (via `@tailwindcss/postcss`), Better Auth (email + password), Drizzle ORM on Neon serverless Postgres. Path alias `@/*` → `src/*`.

## Commands

```bash
npm run dev          # dev server (also regenerates the Next.js block in AGENTS.md)
npm run build
npm run lint         # ESLint (next core-web-vitals + typescript configs)
npm run typecheck    # tsc --noEmit

npm run auth:generate  # write Better Auth tables to src/db/schema/auth.ts
npm run db:generate    # create SQL migration in ./drizzle from schema changes
npm run db:migrate     # apply migrations
npm run db:push        # push schema directly (prototyping only)
npm run db:studio
npm run db:seed       # (re)insert the sample events; replaces rows with the same slugs
```

There is no test runner configured yet.

Env goes in `.env.local`: Next.js reads it, `drizzle.config.ts` loads it explicitly with `dotenv`, and `db:seed` passes it via `tsx --env-file`. Required: `DATABASE_URL` (Neon pooled connection string), `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`. See `.env.example`.

## Architecture

- **DB client** (`src/db/index.ts`): Drizzle over a Neon WebSocket `Pool`, deliberately not `neon-http`, because Better Auth's Drizzle adapter needs transactions. Throws at import time if `DATABASE_URL` is unset.
- **Schema** (`src/db/schema/`): `index.ts` is a barrel; every table file must be re-exported from it, since both the Drizzle client (`schema` option) and `drizzle.config.ts` read from this directory. `auth.ts` is generated by `npm run auth:generate` (re-run it whenever Better Auth plugins/config change); `events.ts` holds `events` 1→many `races`.
- **Auth server** (`src/lib/auth.ts`): `betterAuth` instance using `drizzleAdapter(db, { provider: "pg" })`. `nextCookies()` must stay the **last** plugin so cookies can be set from server actions.
- **Auth HTTP** (`src/app/api/auth/[...all]/route.ts`): catch-all exposing `auth` as `GET`/`POST` via `toNextJsHandler`; all Better Auth endpoints live under `/api/auth/*`.
- **Auth client** (`src/lib/auth-client.ts`): `createAuthClient()` from `better-auth/react`, for client components.

## Database conventions

- **Data access**: all queries live in `src/db/queries/*.ts`, which start with `import "server-only"`. Server components call them directly; don't add API routes for reads. Wrap lookups used by both `generateMetadata` and the page in React `cache()`.
- **Client boundary**: queries map DB rows to plain UI types (`RunEvent`, `Race` in `src/lib/events.ts`) before data reaches components. `src/lib/*` is imported by client components, so it must never import `@/db` or `drizzle-orm`.
- **Enums**: define values once as an `as const` tuple in `src/lib/` (e.g. `EVENT_CATEGORIES`) and pass it to `pgEnum`, so client code gets the list without pulling in pg-core.
- **Schema imports**: files in `src/db/schema/` use relative imports, because drizzle-kit doesn't resolve the `@/` alias.
- **Column choices**: `uuid` PKs with `defaultRandom()`; `timestamptz` for dates; money as `integer` whole pesos (0 = free); child tables FK with `onDelete: "cascade"`; ordered lists read as a whole go in `text[]` columns, not child tables; `numeric` needs `mode: "number"`; enforce invariants with `check()` constraints.
- **Derived values aren't stored**: compute things like `priceFrom` (cheapest race) in the query mapper.
- **Migrations**: edit the schema, `npm run db:generate`, review the SQL in `./drizzle`, then `npm run db:migrate`. Commit `./drizzle`. Use `db:push` only for throwaway prototyping.
- **Seeding**: `src/db/seed.ts` must stay re-runnable (it replaces rows by slug inside a transaction) and close the pool with `db.$client.end()`.
- **Rendering**: DB-backed pages use `export const revalidate = 60` (Cache Components is off). `next build` needs a reachable `DATABASE_URL`.
- **Drizzle gotcha**: don't put `as const` on relational-query `with`/`orderBy` config objects; the readonly arrays fail to typecheck.

## Next.js version notes

This Next.js version differs from older training data; check `node_modules/next/dist/docs/` (`01-app/` for App Router) before writing routing, data-fetching, or config code. For example, layouts/pages use the generated global type helpers such as `LayoutProps<"/">` instead of hand-written prop types.
